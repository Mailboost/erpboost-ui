# 未検証項目の追加検証（2026-10-28）

参照: https://ui.tailor.tech/  
公開先: https://mailboost.github.io/erpboost-ui/

**確認待ちだった5種類のHTML5ドラッグは、ユーザーの許可を受けてPlaywrightのChromiumで追加検証した。参照版・ローカル版・公開版の計15ケースが成功した。コンポーネントへの合成イベントと実ブラウザ操作は区別し、この結果を全操作・全画素の完全一致とは扱わない。**

## 実ブラウザで確認できた操作

1280×720、ライトテーマで参照・公開版を操作した。

| 対象 | 操作 | 結果 |
| --- | --- | --- |
| Timeline | Split後、右端をドラッグして隣の期間を縮める | 両サイトでバーの位置・幅が一致 |
| Timeline | 次のバーの左端を逆方向へドラッグ | 両サイトで元の期間へ戻る |
| Timeline | 境界を左右の端まで動かす | 両サイトで最小1時間の幅を維持し、隣接期間と連動 |
| Gantt | Discoveryバーを右へ20px移動 | 両サイトで開始2026-02-09・終了2026-03-06となり、編集フォームにも反映 |
| Gantt | Discoveryの右端を15px伸ばす | 両サイトで開始日は変わらず、終了日2026-03-11となる |
| Gantt | 開始日を終了日より後へ変更してSave | 両サイトで`Start date must be on or before end date.`を表示し、保存を拒否 |

数値記録は[操作結果JSON](audits/2026-10-28-remaining-interactions.json)に保存した。

## コンポーネントのイベント検証と修正

`npm test`でテストのTypeScript型チェックと13ケースを実行する。jsdomには実際のレイアウトとHTML5のネイティブドラッグ実装がないため、ドラッグイベントと必要な行の矩形をテスト側で与えている。この結果を実ブラウザのHTML5ドラッグ成功とは扱わない。

- 承認段階の前後移動、担当者の保持、キャンセル後の誤ドロップ無視。
- フォーム項目の順序変更と、設定・選択肢・必須・IDを含む生成スキーマの保持。
- パイプライン段階の順序変更、編集中の行をドラッグ対象から外す挙動。
- カンバンの列内移動、カード間の列移動、空の列への移動、コールバックの二重実行防止。
- タイムラインのレーン移動、期間の保持、存在しないバーIDのドロップ無視。
- App infoの既定ルート・メタデータの維持、無効化時の404、検索候補の有効/無効。

テストで次の2件を再現して修正した。この2点は参照との一致を目的とする変更とは分け、不具合修正として扱う。

| 不具合 | 修正前の確認 | 修正 |
| --- | --- | --- |
| カンバンに外部の文字列や壊れたデータを落とすと例外 | 外部テキストと不正JSONで未処理の`SyntaxError`。null・id欠落・不正なidも回帰対象 | カードIDを安全に検証し、不正なドロップを無視。ドロップの既定動作も抑止 |
| カンバンのドラッグをキャンセルしても読み上げ状態が残る | `Picked up draggable item a.`のまま | キャンセル通知と進行中IDの解除。正常ドロップ後の通知はキャンセル通知で上書きしない |

テスト: [ドラッグ処理](../tests/drag-interactions.test.tsx)、[情報ページの設定](../tests/app-info.test.tsx)。CIにも`npm test`を追加した。

## 内部情報ページの相違

カタログは`appInfo={{ enabled: false }}`を指定し、`/__appinfo`を通常の404にする。情報ページの検索候補と専用の静的HTMLも出力しない。ライブラリの既定値は従来どおり有効なので、他の利用先の情報ページは維持される。

## HTML5並べ替えの実操作について

以前の操作ツールでは参照版も並べ替えが完了せず、実操作を未確認としていた。ユーザーがPlaywrightによる検証を許可したため、Chromiumのマウス操作へ切り替えて解消した。ネイティブアプリ操作は再試行していない。

1280×720、英語、ライトテーマ、新しいブラウザコンテキストで、以下を参照版・ローカル版・公開版それぞれに実行した。

| 対象 | 実操作と確認内容 | 3環境の結果 |
| --- | --- | --- |
| PipelineStageManager | LeadをProposalの下へ移動し、元へ戻す。Escapeでのキャンセルで順序が変わらない。編集中はドラッグ無効 | 成功 |
| ApprovalRouteBuilder | 承認段階を前後へ移動。担当者・承認条件を含む生成JSONを保持。Escapeで変更なし | 成功 |
| FormBuilder | フォーム項目を前後へ移動。ID・必須・選択肢等を含む生成JSONを保持。Escapeで変更なし | 成功 |
| Kanban | 列間移動、同じ列内の並べ替え、空になった列へのドロップ。Escapeで変更なし | 成功 |
| Timeline | Phase 1を別レーンへ移動。開始位置・期間の幅を保持。Escapeで変更なし | 成功 |

`dragTo`とマウス・Escape操作を使用し、`dispatchEvent`でDragEventを合成していない。ブラウザが発行した`dragstart`・`drop`・`dragend`を観測し、`isTrusted: true`、変更後の画面状態、キャンセル時にdropが発生しないことを確認した。空列のテストでは当初、48pxの領域外にドロップ点を指定していたためテストを修正し、表示中の列見出しへ落として再検証した。UI不具合として数えていない。

この追加検証で新しいUI不具合は再現しなかった。以前の未確認記載を更新し、[ブラウザテスト](../tests/e2e/native-drag.spec.ts)とCIを追加した。既存13ケースのコンポーネントテスト、型チェックも成功した。

結果とネイティブイベントの記録は[追加検証JSON](audits/2026-10-28-native-drag.json)に保存した。スクリーンショット付きのPlaywright結果は`test-results/native-drag.json`。CIは外部参照サイトに依存しないローカル5ケースを実行し、結果を`browser-test-results`として14日間保持する。

```sh
npx playwright install chromium
npm run test:e2e
E2E_TARGETS=reference,local,published npm run test:e2e
```

文書エディターの埋め込みブロックは、参照版でもマウス操作から`dragstart`が発生しなかった。5種類の並べ替え成功には含めない。カンバンのSpace→矢印→Spaceも参照版で動かないため、キーボードの並べ替え成功とは主張しない。
