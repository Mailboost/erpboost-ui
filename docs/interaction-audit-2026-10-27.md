## 確認の限界

- 38コンポーネントの初期状態と、上記の操作を確認した。全67項目の全操作・全テーマ・全画面幅・全ブラウザの組み合わせを網羅したという意味ではない。
- Markdownのソース本文にはパッケージ名の置換、現行ライブラリへの適合、マスタ保存修正などの意図した差がある。本文のバイト一致は要求しない。
- CSVテンプレートのダウンロード操作は実施したが、検証ブラウザで保存ファイルの取得を確認できなかった。ダウンロードしたファイルの内容は未確認。
- 参照の表示専用Save / Discard / Replyなどは実処理を追加していない。デモ内の保存はコンポーネントのメモリ内状態であり、サーバーへの永続化・メール送信・AI呼出しの検証ではない。

## 第3回の再チェック

375×812pxの検証タブを新しく作り、その同じタブで参照サイトとローカル修正版を順に開くことで、実際のinnerWidthが375pxの状態で比較できた。別の1280×720pxタブでも比較した。実機スマートフォンや複数ブラウザの検証とは区別する。

今回修正した差:

| 対象 | 修正内容 |
| --- | --- |
| 見出し・プレビュー操作バー | モバイルでコピーボタンを別行にしていたレイアウトを修正。画面幅・背景切替の間隔、28pxの操作ボタン、狭い幅での折り返しを参照に合わせた |

| サンプル・説明の間隔 | 複数バリエーション間、共有操作バーの下、ドキュメント補足間の余白を修正。デスクトップの例文も参照と同じ65chで折り返すよう修正 |

測定対象は見出しと、画面内の表・プレビューのx / y / width / height（小数第1位）、ページのscrollWidth。縮小サイドバーの幅アニメーションを待ってから測定した。Webフォントが未読込の一時的な差は、フォント読込完了後に再確認した。画面の全画素、全操作状態の一致を保証するものではない。

日本語でも概要・Sidebar・DatePicker・Collection・Field diff・Chartsの代表6項目を両方の幅で比較し、測定値が一致した。

CSVはテンプレートと同じ見出し（Supplier name / Owner / Status）のUTF-8ファイルを作り、日本語の取引先2件を375px幅で取り込んだ。列の自動対応、検証エラーなし、2行の取込完了まで参照と一致した。ダイアログは375px内に収まっていた。実ERP等へ送信する処理ではない。

テンプレートのダウンロードは再操作したが、検証ブラウザのdownloadイベントは5秒でタイムアウトし、別のファイル取得APIでも保存ファイルを取得できなかった。ダウンロードの成功・失敗は判定できないため、保存されたファイルの確認は引き続き未完了とする。
