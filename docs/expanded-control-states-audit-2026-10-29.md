# 選択欄の空状態・チップ操作・背後の影の追加比較（2026-10-29）

参照: https://ui.tailor.tech/  
変更: [PR #4](https://github.com/Mailboost/erpboost-ui/pull/4)

前回残っていた複数選択候補の上端の差を解消した。さらに、複数Selectと複数Comboboxをすべて解除すると案内文が消える差を修正した。全状態の完全一致とは判定しない。

## 修正した3点

| 対象 | 原因と修正 |
| --- | --- |
| 複数Comboboxの入力欄と候補一覧の上端 | 入力欄の小さい影が不足していた。背後の入力欄へopacity:0を一時的に指定する診断で、候補一覧の差が0になることを確認。通常の部品へshadow-xsを追加した。診断用の非表示指定はアプリへ入れていない |
| 複数Selectの全解除後 | デモのplaceholder指定が不足し、閉じた欄が空白になっていた。参照と同じChoose statusesを指定した |
| 複数Comboboxの全解除後 | デモのplaceholder指定が不足していた。最後のチップを削除すると表示文言と読み上げ名が空になっていたため、参照と同じAssign reviewersを指定した |

影の参照値はライトでrgba(15, 23, 42, 0.06)・0 1px 2px、ダークでrgba(0, 0, 0, 0.35)・0 1px 2px。リングや寸法を変更せず、テーマのshadow-xsを使う。チップへのキー移動、Backspaceでの削除、検索、候補のクリック、削除ボタンのクリックをまたいで影が保たれることも確認した。

以前の候補一覧上端10画素／12画素の差は、PC／モバイル幅それぞれ3回の連続撮影、計6画像すべてで0になった。候補一覧自身のCSSだけを比較していた調査では、背後に重なる入力欄の影を取得できていなかった。前回の未解消という記録は履歴として残し、この調査で原因と解消を追加する。

## 空状態を閉じて確認

複数SelectのDraftとApprovedをすべて解除した後、Escapeで候補を閉じて確認した。開いた候補が入力欄を覆う状態だけでは、案内文の欠落を見落とすためである。

- 英語／日本語 × PCライト1280×900／モバイル幅ダーク375×812の4条件で確認。
- 修正前はPC各620画素、モバイル各614画素の差。修正後は4画像すべて差分0で、案内文・ARIA・フォーカス復帰も一致。
- 参照版では日本語UIでもこの案内はChoose statusesのため、同じ表示を使う。
- 空にした後で再度開き、In Reviewを選んで閉じると値が表示され、欄へフォーカスが戻ることも確認した。

## 最後の担当者を解除した状態

選択済みチップがある間は案内文が隠れるため、担当者の複数Comboboxも0件まで削除して確認した。PC／モバイル幅の両方で、空欄のAssign reviewers・ARIAの名前・入力欄へのフォーカス・Yamadaの再選択が参照版と揃った。

案内文の欠落による画像差はPC624画素／モバイル609画素。修正後は両方2画素の差が残り、最大RGB差はPC2／モバイル7だった。文言の復元と、画素単位の完全一致は区別する。

回帰テストは、候補の終了アニメーション後にDOMが撤去されたことを待ち、ポインターでの削除・最後のチップのキーボード削除・空欄からの再選択まで確認する。終了途中に再検索を始めた試行では参照版でも旧候補が残ったため、その試行も保存した。高速連続操作の全タイミングまで一致を保証するものではない。

英語、Chromium、PCライト1280×900・モバイル幅ダーク375×812。モバイルもマウス／キーボードでの確認で、タッチ実機ではない。
