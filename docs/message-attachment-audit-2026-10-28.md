## 修正した差分

`useAttachment`が新しい添付を既存のファイルの**先頭**に追加していた。参照は**末尾**に追加する。画像／テキストの複数選択、削除後の再選択でも既存の並び順を保つよう、表示用の配列を末尾追加へ変更した。

- 修正前: `新しい添付 → supplier-tax-cert.pdf → logo.png`
- 参照・修正後: `supplier-tax-cert.pdf → logo.png → 新しい添付`

これは追加操作後の画像比較で発見した差分。初回の42操作チェックは追加順を検証しておらず検出できなかったため、既存ファイルと追加ファイル全件の表示順、削除・再選択後の順序を検証するアサーションを追加した。

追加した順序の検証は、修正前の参照でPC・モバイルとも成功し、ローカル・公開版では両条件とも失敗した（計2成功・4失敗）。修正後の参照・ローカルでは追加14ケースずつの計28ケースが成功した。実際のアップロード先へ送信する処理は今回の変更対象ではない。

## 確認した操作

実ブラウザはPlaywrightのChromium。PCは1280×900・ライト、モバイルは375×812・ダーク。各環境で14ケースを追加した。**モバイルのメールとチャットの2ケースは、参照にもある表示制約の再現確認を含み、全機能が操作できる成功ケースではない。**

| 対象 | PCで確認した内容 | モバイルで確認した内容 |
| --- | --- | --- |
| メール | Enter／Spaceでの選択、既読化、検索結果に応じた未読数、大小文字・前後空白、検索0件でも本文選択を保持、メッセージごとのスター、再読込でのリセット | 検索、未読数、キーボード選択。画面外に隠れる操作ボタンは操作成功に数えない |
| チャット | 空白のみでは送信不可、改行入力、会話を切り替えても共通の下書きを保持、デモ送信で入力欄を消去 | 会話切替。幅0の入力欄への入力は成功に数えない |
| 添付コンポーネント | ファイル選択ボタンから画像・テキストを複数選択、既存の後ろへ追加、画像のデコード、メニューをEscapeで閉じた後のフォーカス、削除、同じファイルの再選択、壊れた画像のフォールバック | 同じ操作を確認 |
| スレッドの画像プレビュー | プレビュー表示、実ファイルをダウンロードし元PNGとバイト比較、Escape／閉じるボタン、閉じた後の添付保持 | 同じ操作を確認 |
| スレッドの追加添付 | 複数添付、個別削除、内部メモ切替、Discard後のテキスト・添付・内部メモの状態、デモの操作バッファが1件→0件になること | 同じ操作を確認 |
| スレッドの編集・返信 | 空白編集では保存不可、編集取消、編集保存、別メッセージへの影響がないLike、引用返信と取消、Like解除 | 同じ操作を確認 |

ファイル選択はブラウザのfilechooserイベントを通して行い、画像の読み込みは`naturalWidth`でも確認した。ダウンロードはファイル名の表示だけで判定せず、取得したファイルを読み込んで元PNGと比較した。HTML5でOSからファイルをドラッグする経路やPDFの実表示まで確認したという意味ではない。

## 参照にもある制約

1. **モバイルのメール:** 固定320pxの受信箱が幅を占有し、本文のスター等の操作ボタンが375px画面の外側に隠れる。PCの操作をモバイルでも成功したとは記録しない。
2. **モバイルのチャット:** 固定256pxの会話一覧に対し、テキストエリアの実測幅が0pxになる。会話の切替はできるが、下書き入力の実操作は成功していない。
3. **メールの実処理:** Reply / Reply all / Forward / Archive / Delete / More actionsはこのサンプルでは実処理しない。既読・スターはメモリ内の状態で、再読み込みで初期値に戻る。
4. **チャットの送信:** Sendは入力を消すだけで、メッセージを会話へ追加せず、AIやバックエンドを呼び出さない。会話ごとではなく1つの共通の下書きを保持する。
5. **スレッドの添付:** Discardはテキストだけを消し、追加添付と内部メモのチェック状態を保持する。Send後も添付行が残る。コンソールへの`flushing`出力とバッファの消去を確認したが、実際のアップロードやメール送信の成功ではない。
6. **Markdownの送信:** Sendのハンドラーがなく、押してもメッセージを追加せず下書きを消さない。編集・プレビュー・Discardの操作とは区別する。
7. **既存添付のDownloadボタン:** スレッド内の通常のファイル行ではコンソール出力のみ。実際のファイル取得まで確認できたのは、画像プレビュー内のDownloadリンク。初期PDFには実体のURLがなく、PDF閲覧成功とは数えない。
8. **アップロードの説明文:** 添付コンポーネントの基本例に「Images and PDF up to 20MB.」とあるが、今回の操作では`.txt`も追加できた。20MB境界の制限は未検証。

上記の制約を参照との差分として修正してはいない。カタログの一致と実サービスとしての機能完成は別の判定にする。

## 表示比較

添付を1件追加して削除メニューを開いた状態と、画像プレビューを開いた状態を同じ条件で撮影した。

| 状態 | PC | モバイル |
| --- | --- | --- |
| 修正前の添付メニュー | 参照とローカル／公開版の差分34,976画素 | 同37,914画素 |
| 修正後の添付メニュー | ローカル／公開版とも3画素 | ローカル／公開版とも0画素 |
| 画像プレビュー | ローカル／公開版とも0画素 | ローカル／公開版とも0画素 |

PCの残る差は角丸の輪郭3画素のRGB各1段階。参照サイトを再撮影した画像同士でも、同じ座標に同じ3画素の差が発生した。修正直後のローカル比較では0画素だったが、最終撮影の結果は3画素として記録する。並び順とメニュー位置の差分は解消した。

これは4つの撮影状態の比較であり、全カタログの全状態・全画素が一致したことは示さない。
