# 選択・検索・メニューの追加比較（2026-10-28）

参照: https://ui.tailor.tech/  
公開先: https://mailboost.github.io/erpboost-ui/

今回はSupplier cascaderのグループ選択・検索・追加読み込み、Collectionの絞り込みとページ送り、Menuの状態保持・フォーカス、DataTable内のスクロールを比較した。**メニューを閉じると設定が戻る差分と、フォーカス・チェック表示・表ヘッダの配置の差分を修正した。**

全ページの全操作・全画素が完全一致したという判定ではない。前回までの全ページ確認に、以下の組み合わせを追加した記録である。

## 修正した差分

| 対象 | 修正前 | 修正後 |
| --- | --- | --- |
| Menuのチェック設定 | Notify requester / Auto approve next timeの変更が、ポップアップを閉じて開き直すと初期値に戻る | 参照と同じく、デモの親コンポーネントで値を保持。再表示では保持し、ページ全体の再読込では初期値へ戻る |
| Menuを閉じた後のフォーカス | マウスで項目を操作した後も、Escapeでトリガーへ戻る | 参照に合わせ、項目をマウス操作した後はbody、キーボードだけの操作ではトリガーへ戻る。デモだけに適用し、汎用Menuの既定のフォーカス制御は変更しない |
| 部分選択のアイコン | グループ内の一部だけを選択すると横棒を表示 | 参照と同じチェック印を表示。`aria-checked="mixed"`と選択ロジックは維持する。カタログ内の共有チェックボックスが対象 |
| 選択列のヘッダ | ソートしないヘッダの配置用要素がなく、ヘッダのチェックボックスが約1.5px下へずれる | 参照と同じinline-flex要素で包み、位置を合わせる。表の既存の右クリック・選択・編集の回帰テストも実行 |

Menuの違いは開発版だけでなく、修正前の公開版でも確認した。マウスだけ／キーボードだけ／キーボード移動後にマウス操作の3経路を各2回確認し、操作方法によるフォーカスの違いを分けた。

## 参照側にもあるページ番号の不整合

CollectionのOrdersで、25件表示の2ページ目から`rfq-476`を検索すると、該当する`PO-2026-1036`の1行へ正しく絞られる。一方、ページ番号だけが**`Page 2 / 1`**のまま残る。実データのカーソルとナビゲーションは先頭の1ページとして動き、前後・先頭への移動ボタンは無効になる。表示件数を10へ変更すると`Page 1 / 1`へ戻る。

参照・修正前の公開版・修正版で同じ結果だった。参照との一致を優先し、ERPboostだけで直していない。この問題を含む2ケース／環境には`reference-limitation`注記を付けた。**正常なページ番号表示の成功ではなく、既知の表示不整合の再現を含む。**

## 画像比較

部分選択、検索結果を全17社まで追加した状態、上記のページ番号不整合、設定変更後に開き直したMenuをPC・モバイルで撮影した。フォント読み込みとアニメーションの完了を待ち、同じ領域を比較する。

ローカル8比較では、3比較が差分0画素、残る5比較は1〜11画素に差があり、いずれもRGB各チャンネルの最大差は1／255だった。アイコン形状と表ヘッダ位置の差は修正後の撮影で解消している。小さな画素差を0として扱わず、数値を記録する。

公開反映後の8比較では、4比較が差分0画素、残る4比較は3〜11画素の差で、各チャンネルの最大差は1／255だった。ローカルと公開版を合わせた16比較中7比較が差分0で、残る9比較の数値・範囲もJSONに保存する。

これは特定状態・特定サイズの比較で、全入力値・全サイズ・全アニメーションフレームの一致保証ではない。
