# キーボード・フォーカス・文書編集の追加検証（2026-10-28）

参照: https://ui.tailor.tech/  
公開先: https://mailboost.github.io/erpboost-ui/

以前の初期表示・ドラッグ検証から広げ、15シナリオを追加した。参照版と修正したローカル版で各15件、既存の実ドラッグ各5件も合わせて**40件が成功**した。全入力組み合わせ・全画素の完全一致を示す結果ではない。

## 確認した状態

コンポーネントは1280×720・英語・ライトと、375×812・英語・ダークの両方で実行した。375pxはChromiumの実ビューポートであり、スマートフォン実機ではない。文書編集は1280×900で実行した。

| 対象 | 操作と確認 | 参照・ローカル |
| --- | --- | --- |
| Autocomplete | キーボードで候補を確定し、入力値が候補の全文になる。候補外の自由入力をEscape後も保持、クリア | 両画面幅で成功 |
| Combobox | 単一候補の確定、Backspaceによるチップ削除、複数候補の追加・Escape後の保持 | 両画面幅で成功 |
| Select | キーボード選択、複数選択のSpaceでの解除、Escapeで閉じてトリガーへフォーカス復帰 | 両画面幅で成功 |
| Calendar | 選択できない週末にも矢印でフォーカスを移せるが選択はしない。次の平日を選択し、PageDownで翌月へ移動 | 両画面幅で成功 |
| DatePicker | ポップアップのアクセシブルな名前、読み取り専用値のキー・クリックによる変更抑止、Escapeとフォーカス復帰 | 修正後、両画面幅で成功 |
| Dialog / Sheet | Tab・Shift+Tabのフォーカス制御、画面内に収まる幅、Escape・外側クリックで閉じる、トリガーへの復帰 | 両画面幅で成功 |
| Document | 外部URLの正規化・保存・文書を切り替えた後の保持、内部リンクで文書へ移動、参照先の改名、埋め込み追加・削除、Discardで保存済み本文へ戻る | PCで成功 |

候補の表示とハイライト、ポータルの閉じるアニメーション、フォーカスガードからの復帰が完了してから判定した。閉じる途中の古い候補や一時的なフォーカスを実装不具合として数えない。文書の保存はデモのメモリ内状態であり、バックエンドへの永続化ではない。

## 発見して修正した差分

`Field.Root`内のDatePickerで、明示した`aria-label`から生成するカレンダーの操作名が、自動生成された`Field.Label`のIDに上書きされていた。

| 状態 | 参照版 | 修正前 | 修正後 |
| --- | --- | --- | --- |
| 読み取り専用カレンダーのダイアログ名 | `Locked ship date, choose date` | `Locked ship date` | 参照と一致 |

修正前は同じE2Eテストが参照版のPC・モバイルで成功し、ローカルの両方で失敗した。修正後は全件成功した。呼び出し側で明示する`aria-labelledby`の優先順位を維持し、日本語の`出荷日、日付を選択`もコンポーネントテストで確認した。これはアクセシビリティツリー上の名前の確認で、VoiceOver等による実機の音声確認ではない。

ソース: [DatePicker](../packages/ui/src/components/date-field/date-field.tsx)。テスト: [追加E2E](../tests/e2e/expanded-interactions.spec.ts)、[英語・日本語・aria-labelledby](../tests/date-picker-label.test.tsx)。
